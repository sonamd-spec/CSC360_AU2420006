## Java Files and Streams



In our last week’s class, we covered various concepts from Java Volume 1 and Volume 2. One of the concepts that I learned about is files and streams. File is used to denote a container for holding information while streams are used to read or write data to a program from an outside source. Before coming into this class, I associated the word ‘stream’ with streaming videos. However, from our discussion, I have come to learn that a stream is simply a flow of data from one point to another. For instance, a program can read data from a file by redirecting the data to a stream. Once the data is in a stream, the program can process it and output the results.



This way, I have learned to differentiate files and streams as separate entities used in programming.

Our last week’s lecture also covered data processing and basic statistics. We defined the mean, median, mode, and other statistical terms. ## XML, SVG and Rendering



The last topic that I understood well is XML and SVG. XML is a markup language used to store information. Markup languages use tags to denote specific information. From our class, we also learned that SVG stands for Scalable Vector Graphics. From its name, we can guess that it is used to store graphic images. SVG is closely related to XML because it is essentially an XML language for storing graphics. Because of this, there is always a need to render the information. Rendering refers to the process of using graphic instructions in XML or SVG and displaying it on the screen. For instance, a computer program may have instructions on how a circle should look like, and the size and position it should be found on the screen. The program can then render those instructions into a visible image. From this, I can summarize the process of rendering as;



Data → XML/SVG → Processing → Rendering → Output.



This helped me to understand how data stored in files can be rendered and later displayed.



## Client-Server Architecture



We also covered client-server architecture. This is essentially what websites are; clients and servers. Clients are basically browsers that we use to access websites. Servers on the other hand, are computers that run scripts and programs to supply information to a browser. For instance, if I open a website in a browser, the browser will send a request to a server. The server will process this request and send the response back to the browser. From this, I can summarize the working principle of a client-server relationship as; User → Client → Request → Server → Processing → Response → Client.



From this, I realized that a lot happens in the background of a web application.



## Single Page Applications and JavaScript



The last two topics that we covered are Single Page Applications (SPA) and JavaScript. SPA is a type of web application where the user does not reload the whole page when they navigate from one page to another. In a SPA, only a part of a page is reloaded. For instance, in a web-based accounting application, a user can change the value in an invoice without having to refresh the whole invoice. JavaScript is a scripting language that is mostly used in web development and applications. From this class, I have learned that JS controls how a web application behaves. All of these topics fit together because they are used in developing web applications.
